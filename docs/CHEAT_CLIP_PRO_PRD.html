Product Requirements & Architecture Document

Cheat Clip PRO — AI Auto-Clipper

A plain-language guide to how the product works, exactly where Google Gemini is used, and how to run or rebuild it on a modern stack. Written for stakeholders, operators, and engineers.

Version: 1.0 Document type: PRD + Flow + Replication Guide Audience: Stakeholders, Product, DevOps, Engineers Deploy target: Coolify (Docker Compose) on ARM64

1. TL;DR

One sentence: Cheat Clip PRO turns one long video (YouTube, Google Drive, or an upload) into several ready-to-post vertical clips with animated captions, face-centered framing, and music — in minutes, with no manual editing timeline.

There are two moving parts:

1. The “editor brain” (in this product: Gemini)

Reads the video’s transcript and its audience-retention curve, then decides which moments are worth clipping and writes the titles, captions, and hashtags.

2. The “video factory” (FFmpeg + Whisper + OpenCV/yt-dlp)

Downloads the source, cuts the chosen segments, crops them to 9:16, keeps the speaker centered, burns in karaoke subtitles, mixes music, and exports an MP4 or ZIP.

The AI decides what to clip. The video factory does the clipping. They are deliberately separate so the AI part can be swapped (Gemini today, any model tomorrow) without touching the renderer.

2. Problem & Solution

The problem

  • Long podcasts, streams, and webinars contain a handful of “viral” moments buried in hours of footage.
  • Finding them by hand is slow, subjective, and expensive.
  • Reformatting to vertical + adding captions + reframing the speaker is repetitive manual work.

The solution

  • AI scans the transcript + retention signal and proposes the best clips with timestamps.
  • One studio screen lets a creator restyle and batch-render everything at once.
  • Output is platform-ready (TikTok / Reels / Shorts) with no timeline editing required.

5. The Full User Journey

Paste URL / Upload→ Choose duration & clip count→ Analyze with AI→ Review candidate clips
Open Clip Studio→ Style: frame, captions, face, music, watermark→ Choose encoder (Auto)
Batch Render→ Live progress (streaming)→ Download MP4 / ZIP

Progress is streamed to the browser in real time (Server-Sent Events), so the user sees each stage — download, transcribe, analyze, render — without refreshing.

6. Where Gemini AI Is Used (the important part)

Gemini is used in one place only: after the transcript is ready, to turn it into a structured list of viral clip candidates. Everything else (downloading, transcribing, rendering) is done by non-AI tools.

Source video→ 1. Metadata + retention heatmap→ 2. Transcript acquisition (7 tiers)
3. Language validation (ID / EN only)→ 4. Build prompt + transcript dump→ 5. Gemini call (JSON schema, 120s timeout, model fallback chain)
6. Structured clip candidates→ 7. Present in Clip Studio→ 8. Render

Step 1 — Metadata & the “heatmap”

Before any AI call, the backend fetches the title, duration, and — for YouTube — the audience retention heatmap (the “most replayed” curve). This is the numerical signal of where viewers actually stay. For Google Drive / uploaded videos there is no retention curve, so the app computes an acoustic energy heatmap instead (where the speaker is loudest / most animated).

Step 2 — Getting a transcript (7 tiers of resilience)

The AI is only as good as the transcript. The backend tries, in order, until one works:

Tier 1Supadata cloud API (rotating keys) — reliable cloud-hosted transcript.
Tier 2YouTube transcript API through a rotating residential proxy.
Tier 3Same, but as an isolated CLI subprocess via proxy.
Tier 4yt-dlp native caption extraction via proxy.
Tier 5Direct YouTube transcript API (no proxy).
Tier 6Direct CLI subprocess (no proxy).
Tier 7Direct yt-dlp native extraction (no proxy).
FallbackWhisper AI speech-to-text (local) — used when no caption track exists at all, e.g. uploads or Google Drive files.

Every transcript is also validated for language: the product is intentionally scoped to Indonesian and English. Non-matching tracks are rejected and the next tier is tried, ending with Whisper.

Step 3 — Prompt assembly

The transcript is flattened into compact start|end|interest text lines (capped at 2,000–3,500 lines to control token cost) and packed into a system-style prompt that tells Gemini to act as an expert short-form editor. The prompt enforces hard rules:

Rule in the promptWhy it matters
Output 100% in the video’s spoken language (ID or EN); never translate.Stops English captions appearing on Indonesian videos, etc.
Clips must start/end on sentence boundaries and never overlap.Prevents mid-word cuts that feel broken.
Respect the chosen duration (15/30/60s or dynamic Auto up to 90s).Matches the platform format the user wants.
Titles must never use first person (“I”, “saya”, “aku”).The poster is a curator, not the speaker; avoids misleading clips.
Attribute to the real speaker/channel when known.More credible, more clickable titles.
Optional custom search focus (“find clips about X”).Lets users target a theme without changing the video language.

Step 4 — The Gemini call & its guardrails

  • Model: defaults to gemini-2.5-flash; the app discovers the newest available Flash models for the user’s key and builds a fallback chain (top 4).
  • Structured output: requests strict JSON (response_schema = the video-analysis schema), temperature 0.2 (deterministic), max_output_tokens 65536.
  • Timeout & retries: 120s per model, one transient retry, then automatic fallback to the next model.
  • Streaming UX: while the model “thinks”, the UI shows fabricated-but-honest stage messages (context loading → retention cross-analysis → hook detection → boundary snapping → virality scoring).
  • Mock mode: typing mock as the key returns sample data so the whole pipeline can be demoed without an API key.

Step 5 — What Gemini returns

// simplified shape of each candidate clip
{
  "summary":            "what happens in the clip",
  "title":              "catchy title, <= 8 words",
  "title_suggestion":   "alternative title",
  "caption_suggestion": "engaging social caption",
  "hashtag_suggestion": "#relevant #hashtags",
  "key_quotes":         ["verbatim quote from transcript", "..."],
  "start":              142.0,
  "end":                168.5,
  "virality_score":     92
}

The result is sorted by virality_score, so the user sees the strongest candidates first. These become the selectable cards in the Clip Studio.

Where Gemini is NOT used: it never touches the video pixels. It does not download, cut, crop, caption, or encode. That keeps cost low (text-only calls) and keeps the AI swappable.

8. The Rendering Engine

  1. Download the source segment

    yt-dlp pulls only the needed time range (or the full file for uploads/Drive).

  2. Detect the speaker

    OpenCV (Haar cascade + YuNet saliency) finds the face so the crop stays centered on the active speaker.

  3. Cut & reframe

    FFmpeg crops to the chosen aspect (9:16 / square / split-screen facecam).

  4. Burn captions

    An ASS subtitle file with word-level karaoke animation is rendered via the libass filter.

  5. Add branding & audio

    Watermark/logo overlay, background music, and hook SFX are mixed in.

  6. Encode with the best available encoder

    Auto-detects NVIDIA NVENC → AMD AMF → Intel QSV → CPU libx264 (the ARM/Coolify default).

  7. Package

    Clips land in exports/ and are offered as individual MP4s or a single ZIP.

On ARM servers (like your Coolify box): there is no NVENC/QSV, so the engine cleanly falls back to CPU libx264. Threads are capped (2 by default) so rendering stays stable on a small machine.

9. How It Deploys on Coolify (Docker Compose)

The repository ships a two-service docker-compose.yml and two Dockerfiles. Coolify’s Docker Compose build pack reads them directly; images build natively for ARM64 — no emulation.

# services
backend   -> Dockerfile.backend    (FastAPI + FFmpeg + yt-dlp + Whisper, internal port 8000)
frontend  -> Dockerfile.frontend   (Vite build served by nginx, publishes port 80)

  1. Push the repo to Git

    Coolify deploys from a Git source (GitHub/GitLab or your own).

  2. Create a new Resource → Docker Compose

    Point it at the repo. Coolify detects docker-compose.yml.

  3. Set the exposed port to 80

    Only the frontend publishes a port; the backend stays on the private network. Map your domain to the frontend.

  4. Add environment variables

    Optional: GEMINI_API_KEY, SUPADATA_API_KEYS, ADMIN_API_KEY, and resource limits (see below). Users can also paste their own Gemini key in the UI.

  5. Deploy

    First build downloads Python/Torch/Whisper once; subsequent deploys are cached and fast.

  6. Health checks

    Frontend: nginx /healthz. Backend: /api/health. Coolify shows both as healthy.

Sizing note. The compose file defaults the backend to 3 GB RAM / 3 CPU (BACKEND_MEM_LIMIT, BACKEND_CPUS). If your server has more RAM, raise BACKEND_MEM_LIMIT so long videos and Whisper have headroom; keep it below the host’s total RAM so Coolify’s proxy and the OS stay responsive.

11. How to Replicate or Improve It

11.1 If you keep the current architecture

  • Add a small job queue + worker (Redis/RQ or Celery) so renders survive restarts and can scale horizontally. Today job state is in one process.
  • Move media to object storage (S3/R2) instead of Docker volumes for durability and multi-replica scale.
  • Cache transcripts and Gemini results per video so re-analyzing is free and instant.

11.2 Recommended “better stack” for a rebuild

ConcernCurrentUpgrade suggestionWhy
Transcriptionopenai-whisper (base, CPU)faster-whisper or WhisperX (CTranslate2, INT8)5–10× faster on CPU, far lower RAM, better word timestamps — ideal for ARM.
AI selectionGemini Flash onlyProvider-agnostic layer (Gemini / GPT / Claude / local)Cost and quality flexibility; avoids single-vendor lock-in.
API/backendFastAPI monolithKeep FastAPI, extract render into a worker serviceReliability, retries, autoscaling.
StateIn-memory dictsRedis for state, Postgres for historyDurable job tracking and per-user history.
StorageDocker volumesS3-compatible object storageScales beyond one box; survives redeploys.
Encodinglibx264 CPU on ARMVertical ARM GPU / dedicated render node, or queue to a GPU workerRendering is the CPU bottleneck on ARM.
AuthNone (open)Accounts + API keys + quotasRequired for any multi-user/SaaS form.

11.3 UI / UX improvements (making it friendlier)

Guided 3-step wizard

New users often don’t know the order: Source → Analyze → Style → Export. A stepper beats a dense studio screen for first-timers.

Preset templates

One-click looks (“Podcast Clip”, “Gaming Short”, “Talking Head”) instead of configuring 20 controls.

Instant preview

Render a short watermarked preview of the first 3 seconds before the full batch, so users trust the style.

Honest progress

Show real ETA and queue position; renders can take minutes on a small server.

Clip library + history

Persist past batches so users can re-download without re-rendering.

Inline AI editing

Let users tweak a title and “regenerate” just that field via the AI.

11.4 A product roadmap (milestones)

  1. MVP (what exists)

    Single-user self-hosted clipper with Gemini + FFmpeg + Whisper.

  2. Reliability

    Worker queue, object storage, transcript/analysis caching.

  3. Multi-user

    Accounts, per-user API keys, quotas, history.

  4. Faster inference

    faster-whisper + GPU/ARM-optimized rendering node.

  5. Distribution

    Direct publish to TikTok/YouTube/Reels, scheduling, analytics on which clips perform.
